# Try Reopen's prototype

Reopen preserves why a project decision made sense, puts later evidence beside its original assumptions, and asks the owner to approve an exact checklist change.

1. Follow the [local setup](README.md#run), create an account and choose **Explore an illustrative example**. Every example record is fictional.
2. Read the confirmed decision and its original rationale. Compare the later explicit report with the separate hypothetical question.
3. Review the exact evidence, enter your reason and explicitly reopen the decision. Draft the checklist replacement, inspect its before/after text and approve it separately.
4. Open the decision history. The original reasoning and approved change remain recorded. Reload to confirm persistence.

The optional Bee connection requires the official CLI on the same trusted local machine and the configured owner's account. Read [the connector setup](README.md#connect-real-bee-conversations) before using real conversations. Import only recordings for which you have permission. Manual imports remain manual even if a filename says Bee.

No Bee device or Apple Watch recording has been available for this project. Reopen is a public prototype and has not been submitted as a qualifying Bee entry. The [event rules](https://amazonappdev2026.devpost.com/rules) require actual Bee device data. Passing fixture tests cannot satisfy that requirement.

The **Judge checks** workflow exercises consent, selected fixture imports, explicit wording review, deduplication, separate checklist approval, and delayed responses across notebook/account changes. Triage uses conservative lexical rules; it does not understand every semantic change or verify a speaker's assertion. Real-user usefulness remains unmeasured.
